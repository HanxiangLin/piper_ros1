# 实时扫描 + 语义避障 + 抓取放置

`moveit_grab.py` 的当前版本在启动后自己完成“扫视 — 冻结 — 避障 — 抓取 — 放置”，不再需要
离线 `table_model.json`，也不需要手工开关静态扫描门。

## 1. 启动前提

1. `move_group` / 机械臂驱动 / 夹爪服务已经在运行（`piper_real.launch`）。
2. **ROS 相机节点必须停止**：程序自己用 `pyrealsense2` 打开 D435i，否则设备被占用会直接报错。
3. 机械臂停在操作者确认安全的位置。第一段“当前位 → `scan_start_joint_target`”没有地图保护
   （OMPL 随机规划，理论上可能先下沉再抬升），必须人工确认该路径不会碰到任何东西。
4. 扫描期间工作区保持静止（人和物都不要进出视野）。

## 2. 一次运行的顺序

```text
清场：删 table/target_bottle/scan_obstacle_*、清 OctoMap、复位 ACM、关闭遗留扫描门
张开夹爪（原地）
OMPL 运动到 scan_start_joint_target
视点0：停稳 → 取4帧 → 逐帧投票去噪 → 融合 → RANSAC拟合桌面 → 桌面进场景
       → YOLO识别全部物体 → 点云聚类/形状判别 → 目标瓶进场景、其余进障碍
视点1：joint1 +0.357rad → 同上（换姿轨迹已在视点0地图上规划）
视点2：joint1 -0.357rad → 同上
冻结：场景签名 = OctoMap + 全部世界对象（桌面/目标瓶/障碍）
抓取：接近走廊预筛 → 预抓取规划 → 虚拟起点验证直线接近 → 执行 → 夹紧确认 → 附着 → 抬升
回零：夹着瓶子先回 home_joint_target = [0,0,0,0,0,0]（避免"低姿横伸"直接横移到放置位）
放置：按扫描到的卡面法向，在卡面前 place_offset_from_card 处、桌面+间隙高度松手
      下降优先走直线；直线被截断时自动退回 OMPL 规划到同一目标位
回零：放置完成后再回零位
```

每一步运动前都会重新比对场景签名；签名变化立即中止，不自动回零、不自动松爪。
规划失败时会补一次**可达性诊断**：用多组初值解 IK 并检查碰撞，把"KDL 无解"或
"与 `scan_obstacle_0` 碰撞"这类原因直接拼进异常信息。它是诊断，不是闸门——
单初值 IK 对折得很紧的合法位姿会误报，所以**不会**在规划前拦截动作。

## 3. 关键参数

| 参数 | 含义 |
|---|---|
| `scan_start_joint_target` | 第一个视点的关节角，必须能同时看见瓶子和卡片 |
| `scan_joint1_offsets` | 相对起始位的 joint1 偏移，默认 3 个视点 |
| `scan_settle_time` / `scan_frames_per_view` | 每个视点停稳时间 / 取帧数 |
| `scan_min_frame_votes` | 同一体素至少被几帧看到才保留（抗飞点、反光） |
| `scan_min_views` | 融合点至少被几个视点看到（1=任一视点即可，避免漏障碍） |
| `scan_voxel_m` | 融合体素，默认 6mm |
| `scan_roi_min/max` | base_link 下的扫描区域；`z` 下限要高于地面、低于桌面 |
| `scan_mode` | `semantic`（默认）或 `both`（另把剔除目标瓶后的点云喂给 OctoMap） |
| `scan_min_obstacle_height` | 桌面以上低于该高度的点视为桌面本身（纸板起伏/印刷纹理） |
| `scan_card_padding` | 卡片薄盒的外扩量（默认 5mm；其它障碍仍用 `scan_obstacle_padding`） |
| `scan_stand_max_distance` / `scan_stand_max_thickness` | 卡片附近这个范围内的薄板视为支架，**不加入障碍集** |
| `scan_card_carve_margin` | 后续视点重建障碍时，抠掉已锁定卡片包围盒的外扩量 |
| `scan_card_min_extent` | 卡片最小边长；20×15cm 卡片默认 0.10 门槛 |
| `scan_corridor_radius` | 接近走廊净距；小于该值的接近方向直接跳过并报出阻挡物 |
| `place_offset_from_card` | 松手点距卡面中心的法向距离，默认 0.11（19×15cm 倾斜卡片，0.09 时下降会被卡片上沿截断） |
| `place_front_mode` | `card_normal`（默认，按拟合卡面法向）/ `toward_robot` / `fixed_yaw` |
| `home_joint_target` | 放置完成后的回零目标 |

目标瓶与卡片的区分**只用几何**：卡片是薄板（平面度高、双向展开大、厚度远小于尺寸），
瓶子是圆柱（拟合半径/高度与参数一致）。因此“卡片上印着同色瓶子照片”不会导致抓错。

三条防止“幽灵障碍”的规则：

1. **只有被判成圆柱的簇才用实测半径建圆柱**；`unknown` 一律用 AABB（曾经把
   “卡片+桌面噪声”拟合成 r=15cm 的圆柱，直接把放置位包住）。
2. **卡片角色在第 0 视点锁定**（正面视角最干净）。后续视点只精修目标瓶中心，
   重建障碍前先把“已锁定卡片包围盒（外扩 2cm）+ 目标瓶圆柱”从融合点云里抠掉，
   避免侧视角把卡片和背景点连成一团后重新分类。
3. **簇级最低高度过滤**：桌面以上 <2cm 的簇视为桌面本身，不建障碍。
4. **薄板用斜的薄盒（OBB）**：`unknown` 但平面度好的簇不再退化成大 AABB，
   否则一块 23×9×0.4cm 的斜板会被画成 17×13×19cm 的方块。
5. **卡片支架不算障碍**：卡片中心 25cm 内、很薄且平面度好的簇判为支架并排除
   （操作者确认：瓶子只会放在卡片正前方，永远碰不到支架）。

## 4. 每次扫描的落盘产物

`scan_artifact_root/scan_<时间戳>/`：

- `cloud.npz`：融合点云 `points` 与每个点的 `observations`（被几个视点看到）
- `table_model.json`：本次拟合的桌面（与旧离线格式一致，可直接用于排查）
- `scene.json`：目标瓶中心、卡片模型、障碍列表、YOLO检测结果
- `summary.txt`：人读摘要
- `view_<n>.png`：每个视点的彩色图

参数调不好时先看 `summary.txt` 和 `scene.json`，再决定改 ROI、聚类体素还是判别阈值。

## 5. 常见失败与含义

| 报错 | 原因 / 处理 |
|---|---|
| `扫描ROI内有效点不足` | 视点看不到桌面、ROI 设错、深度无效 |
| `桌面平面占比不足` | ROI 里混入太多非桌面点（墙、地面、箱子） |
| `未找到圆柱形目标瓶` | 瓶子被遮挡、点太少、聚类太碎（调 `scan_min_cluster_points`） |
| `存在多个圆柱候选` | 桌上不止一个瓶子；用 `target_bottle_label` 按颜色区分 |
| `扫描未识别出卡片` | 卡片被遮挡或只露出一部分（`scan_card_min_extent` 太大） |
| `目标瓶在多视点融合中丢失` | 某个视点看不到瓶子，换 `scan_joint1_offsets` |
| `没有可行的接近走廊` | 目标瓶被其他障碍包围；日志会给出阻挡物 id 和净距 |
| `环境/规划场景在任务中改变` | 有人动了场景、或遗留扫描门又在发点云 |

## 6. 已知边界（本次明确的取舍）

- **相机/支架没有几何模型**。它们装在 link6 上方，场景里没有悬挑类障碍时不会被碰到；
  但正上方有悬空物时规划器看不见它们。用 `scan_corridor_radius` 留的余量不能替代真实包络。
- **冻结后新增的障碍看不见**。这与旧静态扫描的边界一致，程序只在运动前校验场景签名。
- **扫描期只做帧间投票**，不做“两次扫描差分”一致性检查；扫描期间不要让人或物进入视野。
- **第一段运动无地图保护**，这是取消预览模式和人工确认后的固有风险。
- `both` 模式只把“桌面以外、目标瓶以外”的点云喂给 OctoMap，桌面和目标瓶仍由精确语义体表示；
  OctoMap 侧仍会有 `padding_offset` 的 3cm 膨胀，因此默认推荐 `semantic`。
